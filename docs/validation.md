# v3.6.0 验证记录

## 方法

2026-09-21 在 Apple Silicon Mac 的 Safari / Tampermonkey 5.6.6240 中测试。使用同一公开直播间、原画 2560×1440、60 fps、HEVC、1/4 屏弹幕与七项特效屏蔽。

测量口径为目标 WebContent 进程的 physical footprint，不是 RSS 或虚拟地址空间。A/B 各使用独立的新页面进程，从页面年龄约42秒开始采样120秒，每10秒一条。视口均为887×782。第一次复用了旧进程的 B 样本已排除。

| 样本 | 起点→终点 MiB | 范围 MiB | 平均 MiB | 新增掉帧 |
|---|---:|---:|---:|---:|
| v3.5.0，120秒 | 794.2→807.3 | 793.6–807.3 | 797.2 | 0 |
| v3.6.0 资源拦截阶段，120秒 | 460.6→460.7 | 460.1–472.3 | 462.7 | 0 |
| v3.6.0 最终版，300秒 | 437.4→432.9 | 414.8–472.0 | 433.8 | 0 |

A/B 平均下降42%。最终版额外卸载6个广告/连麦模块，提前拦截辅助根渲染并清空残留静态节点；其采样时长不同，不将两行合并成时长匹配的对照。

最终页外部脚本节点由旧版162降至102；iframe由3降为0；22个非核心播放器模块卸载，原生播放器模块从34降至28。最终版更早阻止辅助根渲染，因此资源拦截计数49低于阶段版本105，这不表示加载资源反而更多。

## 功能验证

- 首次最高档流请求在约256ms发出，首个2560×1440视频在约964ms出现。
- 实际媒体信息60fps、HEVC，5分钟新增掉帧0。
- 七项屏蔽、1/4屏设置与原生发送服务保持。
- 使用 MCP 对同一房间复核动态弹幕、原画2K60、全屏/非全屏回车聚焦输入框，结束时恢复前台网页全屏。
- 未实际向直播间发送测试弹幕；鉴权和发送继续依赖原生服务。
- Node.js语法与规则测试通过。

## 解释限制

直播内容和弹幕无法锁定，只有一组顺序A/B，不代表跨房间、跨浏览器版本或长时间使用的固定收益。本次验证侧重目标进程内存，原页面曾自行恢复播放，因此不将其当作严格单路播放的CPU/系统功耗对照。

此前约1.8GiB的高占用还包含旧页面上下文、缓存或分配器状态，不能全部归因于业务模块。本次一次性重建标签释放旧上下文的效果与代码改动分开统计，脚本没有定时重载/杀进程机制。

诊断阶段一次Web Inspector堆快照在JSON序列化阶段触发WebContent崩溃并自动重载。该事件发生在上述受控对照前，未用于证明正常播放的泄漏，也没有计入最终连续播放结果。后续仅用轻量采样。

共享房间基础库仍然包含业务代码。直接阻断其中部分分包会破坏控制栏启动，相关实验已回退；最终策略是保留核心依赖并卸载非核心组件。数小时/整夜、特殊房间、真实发送、系统级功耗和全部WebKit内存回收问题仍有未验证边界。

这里只公开汇总结果，不发布个人浏览器日志、进程堆、会话地址、账号数据、截图或下载的第三方网页脚本。
