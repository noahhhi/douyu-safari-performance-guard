# v3.6.1 切房与历史缓存修复

## 触发与原因

用户报告没有手动刷新、点击进入直播间后约 949 MB。本次对原进程首次读到 physical footprint 942.6 MiB，后续诊断中达到 1257 MiB。当前页仍只有一个视频、没有 iframe、无限 FLV preload 防护有效，正常直播缓冲约 21 秒。

旧版离开时实测 `pagehide.persisted=true`，原生播放器 `destroy()` 未调用：Safari 缓存了旧文档及播放器上下文。仅销毁播放器后，同进程对照仍出现约 565→695 MiB 的一次导航增长，因此需要同时处理整个历史文档的缓存路径，不能只卸载播放器或隐藏 DOM。

## 实现

- 离开页面时调用原生播放器的 `destroy()`，由其使用匹配的 React renderer 卸载自身根并清理原生服务，再释放媒体源、发送服务、脚本观察器和挂钩。
- 同源 GET 导航在当前或目标为数字房间时，先保存正确的历史 URL，再执行整页加载，包含直播间到目录的退出路径。WebKit 对 Reload 导航不缓存离开的文档；实测从 `persisted=true` 变为 `false`。
- Navigation API 覆盖普通链接和脚本导航；旧 Safari 使用普通同标签链接与 History API 回退。保留表单、下载、hash、查询参数记账及历史遍历。
- 只切换到后台不销毁播放器，不用定时刷新、自动杀进程或强制垃圾回收。

源代码依据：[WebKit BackForwardCache.cpp](https://github.com/WebKit/WebKit/blob/main/Source/WebCore/history/BackForwardCache.cpp)。这不是对 Safari 全局缓存设置的修改。

## 验证

同一 WebContent 进程连续测试进入另一房间、返回原房间、后退两次、前进两次。六次离开均记录 `persisted=false`，原生播放器销毁一次、媒体源释放一次，清理异常为空。每阶段结束时都恢复了对应直播播放，原房间为 2560×1440，另一房间为 1920×1080；六轮观测中未增加掉帧。

另行验证 `history.pushState` 从数字房间到 `/directory`：旧播放器销毁一次，`persisted=false`，目录页媒体元素为 0；再次通过 History API 进入房间后，v3.6.1 防护在新文档中正常启用。

| 阶段 | 阶段末 physical footprint |
| --- | ---: |
| 新标签原房间，60 秒参考样本 | 481–492 MiB |
| 切换到另一房间 | 616.89 MiB |
| 返回原房间 | 706.97 MiB |
| 后退到另一房间 | 810.22 MiB |
| 后退到原房间 | 893.56 MiB |
| 前进到另一房间 | 943.78 MiB |
| 前进到原房间 | 926.38 MiB |

**这些结果证明导航与原生清理生效，但没有证明全部内存问题解决。** 随后的常驻播放仍约 933–957 MiB。原生 heap 统计可见 35 个 HTMLDocument、7 个 HTMLVideoElement，但只有 1 个 MediaSource、2 个 SourceBuffer、2 个 WebSocketChannel。旧对象仍在，不等于七路视频仍播放；其最终保留来源与回收时机尚未确定，不能把全部差额归于缓存或断言已根治泄漏。

对象诊断会短暂停顿进程，因此其间出现的掉帧不纳入前述正常播放观测。一次通过 AppleScript 设置地址的无网页探针对照复用了旧进程，且加载类型为 navigate，未满足匹配条件，未用作内存效果对比。

用户随后自行关闭 Dark Reader 自身的全局开关；未修改其 Safari 网站权限或恢复启用。等待旧直播进程实际退出后重新测试：原房间稳定样本约 419–423 MiB，切到另一房间阶段末 635.97 MiB，返回原房间 60 秒后 721.64 MiB；两次离开均 `persisted=false`，原生销毁/媒体释放各一次，无清理异常或新增掉帧。说明关闭主题并未消除切房增长，不能把残留问题归因于 Dark Reader，也不是对所有扩展的完整隔离实验。

## 限制与回退

旧版已缓存的文档不会被安装新脚本追溯清理。本机对测试直播标签做过一次性重建；该回收效果独立于后续同进程导航测试，不把旧高占用到新标签的全部下降归功于代码。

当前方案取消可拦截的跨文档 Navigation API 导航并发起新的加载，因此主动调用 `navigation.navigate()` 的网页代码可能观察到原导航 Promise 的 AbortError。已排除 POST 表单、下载和 same-document 操作；站点未来变更仍需回归。跨域离开、旧 Safari 回退路径和任意第三方脚本组合没有完整覆盖。

诊断中试验过仅对房间主文档修改 Cache-Control 的扩展网络规则，当前 Safari 上未得到预期 BFCache 效果，已移除并确认动态规则恢复为空。最终修复不依赖该规则，也不增加扩展权限。

禁用用户脚本并重新加载可停止修复；播放器偏好沿用原生设置，不自动回滚。
